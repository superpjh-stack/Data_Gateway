# UI_DESIGN — 수집 현황 대시보드

## 1. 방향

산업용 관제(HMI/SCADA) 화면이다. ISA-101 고성능 HMI 원칙을 따른다.
- 평상시에는 회색조로 조용하게 두고, **이상 상태만 색으로 드러낸다.**
- 상태는 색 + 아이콘 + 글자로 함께 표시한다(색각 이상 대응).
- 숫자가 주인공이다. 고정폭 숫자, 오른쪽 정렬, 단위는 작고 흐리게 쓴다.
- 노트북(1280px)과 65인치 현황판(3840px) 모두에서 읽혀야 한다.

| 상태 | 색 | 아이콘 | 라벨 |
|---|---|---|---|
| OK | `--ok` | ● | 정상 |
| DELAY | `--delay` | ▲ | 지연 |
| DOWN | `--down` | ✕ | 끊김 |
| ERROR | `--error` | ■ | 오류 |
| STALE | `--inactive` | ◌ | 갱신없음 |
| INACTIVE | `--inactive` | – | 비활성 |

- 글꼴: Pretendard Variable(본문), JetBrains Mono(숫자·주소). `@fontsource`로 로컬 번들한다.
- 크기: 기본 `clamp(13px, 0.75vw, 28px)`. 현황판에서 비율로 커진다.
- 간격은 4px 그리드, 모서리 6px, 그림자 없이 1px 보더를 쓴다.
- 값이 바뀌면 배경을 400 ms 동안 accent 12%로 플래시한다.
- 새 알람은 배너가 1회 펄스한다. 계속 깜빡이지 않는다.
- `[가정]` 배지: `--delay` 색의 점선 테두리 + "가정" 글자

## 4. 화면

### UI-01 상단 요약
- 구성: 정상/전체 장비, 1분 성공률, Edge 버퍼 대기, 활성 알람, MES 링크, WS 연결, 시각
- 데이터: WS `summary`(1 s), `GET /api/summary`(초기값)
- 상태: WS가 끊기면 "WS ✕ 재연결 중" 배지를 붉게 표시하고 마지막 값은 흐리게 유지한다

### UI-02 수집 토폴로지 (개요 화면 본문)
```
 센서/설비               버스/직결        PLC           Edge       MES
 ● SAL-01 ─┐
 ● SAL-02 ─┤
 ● THD-07 ─┼── M1 ● ─┐
 …         │         ├── Master ● ──┐
 ● TC-01  ─┼── M2 ✕ ─┤              │
 ● MD-01  ─┘         │              ├── Edge ● ── MES ●
 ● SAN-01 ── ETH ────┘              │
 ● THD-01 ─┬── S1 ● ──── Slave ● ───┤
 …         │                        │
 ● PKG-01 ── OPC-UA ────────────────┤
 ● SCALE-01 ─ RS-232 ───────────────┤
 ● FILL-01 ── ETH ──────────────────┤
 ● STUFF-01 ─ ETH ──────────────────┘
```
- SVG로 그린다. 링크 색은 하류 노드 상태를 따른다. 노드를 클릭하면 UI-05로 간다.
- 데이터: WS `topology`(1 s), `GET /api/topology`
- 빈 상태: "토폴로지 불러오는 중" 스켈레톤

### UI-03 공정 현황
- 9개 공정 열(입고/보관 → … → 냉장·숙성)을 가로 스크롤로 배치하고, 각 열에 장비 카드를 둔다
- 장비 카드: 상태 아이콘, 설비 코드, 이름, 대표값 1~2개, `[가정]` 배지
- 절임통 그리드 4×2: 통번호, 목표 염도, 현재 염도, 경과시간, 담당 센서, 측정중(●)
- 데이터: `GET /api/equip`, WS `value`, `GET /api/tanks`

### UI-04 수집 현황 표
- 열: 상태, 설비 코드, 장비, 공정, 통신, 연결, 주기, 성공률 1분/1시간, 평균 응답(ms), 마지막 수신, 타임아웃/CRC/예외/프레임, 가정
- 정렬(머리글 클릭), 필터(상태·통신·공정·검색어)
- 데이터: `GET /api/equip` 2 s 폴링 + WS `equip_status`

### UI-05 장비 상세 (`/equip/:code`)
- 머리: 상태, 이름, 통신·연결, PLC 블록 주소, 가정 항목 목록
- 태그 표: 항목, 값, 단위, 품질(GOOD/STALE/FILTERED), 레지스터/노드, D주소
- 추이 차트: 최근 1시간 항목별 라인(ECharts, 이상 구간 음영 없음, 기준선 점선)
- 원시 프레임: 최근 50건(시각, 방향, 16진, 결과)
- 데이터: `GET /api/equip/{code}`, `GET /api/raw?equip=`, `GET /api/equip/{code}/frames`

### UI-06 PLC 메모리
- Master / Slave 탭. 10열 그리드(행 = D0100, D0110 …)이며 블록 경계와 설비 코드 라벨이 있다
- 셀: 10진 값, 마우스를 올리면 `D0122 · THD-07 온도 원시값 253 → 25.3 ℃`
- 진단 영역 D0900~D0905는 별도 카드로 보여준다
- 데이터: `GET /api/plc/{id}/memory` 1 s 폴링, 바뀐 셀 플래시

### UI-07 Edge 버퍼
- KPI: 대기 샘플/항목, 누적 전송, 재전송, 보존 초과 삭제, 가장 오래된 대기 시각, 링크 상태
- 차트: 대기 항목 추이(최근 10분)
- 데이터: `GET /api/edge/buffer` 1 s, WS `edge_buffer`

### UI-08 수집 원장
- `IF_SENSOR_RAW` 최근 200행 표. 필터: 설비, RESEND_YN, 기간
- 우측 카드: 분배 테이블별 행 수
- 데이터: `GET /api/raw`, `GET /api/tables/stats`

### UI-09 알람
- 활성 알람 카드 목록(심각도, 설비, 메시지, 값, 경과시간, [확인])
- 이력 표(기간·분류·설비 필터), CCP 기준표(설계/가정 배지)
- 데이터: `GET /api/alarms`, `POST /api/alarms/{id}/ack`, `GET /api/ccp`, WS `alarm`

### UI-10 시뮬레이션 제어
```
 대상 [SAN-01 ▾]  유형 [value_spike ▾]  항목 [농도 ▾] 값 [8.5]  지속 [180]s  [적용]
 프리셋: [HACCP 소독수 이탈] [냉장고 문 열림] [Master 버스 M2 단선] [MES 회선 10분 장애]
 ─ 활성 고장 ─────────────────────────────────────────────
 F-3  SAN-01 value_spike 농도=8.5    남은 02:41   [해제]
```
- 유형에 따라 대상 목록을 바꾼다(버스 유형 → M1/M2/S1, plc_down → MASTER/SLAVE …)
- 데이터: `GET /api/sim/catalog`, `GET/POST/DELETE /api/sim/faults`, `POST /api/sim/scenarios/{name}/run`

## 5. 공통 상태 처리

| 상태 | 표시 |
|---|---|
| 로딩 | 회색 스켈레톤 블록 |
| 빈 데이터 | 가운데 흐린 문구 ("아직 수집된 데이터가 없습니다") |
| API 오류 | 본문 상단 붉은 한 줄 + [다시 시도] |
| WS 끊김 | 상단 바 배지, 1→2→4…10 s 재연결, 재연결 후 스냅샷 복원 |
